\subsection*{A1. State abstraction of the 1-D grid MDP}

No. Abstracting the state into $L$ and $R$ does not turn this into an MDP. An MDP assumes the agent knows exactly which state it is in. Here the true state is still uncertain: we only believe the agent is somewhere on the left side or the right side, not exactly where. The agent therefore still needs a belief, a probability distribution over the possible states, so the problem remains a POMDP.

\paragraph{(b) Pruning by pointwise dominance.}
From Figure~\ref{fig:alpha-vectors}, $\alpha_4$ and $\alpha_5$ lie strictly below the maximum for every belief $p\in[0,1]$, so both can be removed by pointwise dominance. The maximum is
\[
V_{\max}(p)=\begin{cases}
V_{\alpha_2}(p)=10-15p, & 0\le p\le 0.4,\\
V_{\alpha_3}(p)=4, & 0.4<p<0.6,\\
V_{\alpha_1}(p)=15p-5, & 0.6\le p\le 1.
\end{cases}
\]
For all $p\in[0,1]$, $V_{\alpha_4}(p)=2-p<V_{\max}(p)$ and $V_{\alpha_5}(p)=4.5p+1<V_{\max}(p)$. The dominating vector may differ with $p$. In contrast, $\alpha_1$, $\alpha_2$ and $\alpha_3$ each attain the maximum on an interval, so they cannot be removed.

\subsection*{B1. MDP framing of multi-drone navigation}

\begin{itemize}
  \item \textbf{State space} $S$: each state contains the positions of all $N$ drones, $s=(p_1,\dots,p_N)$, where $p_i=(x_i,y_i,z_i)$. 
  \item \textbf{Action space} $A$: A joint action $a=(a_1,\dots,a_N)$ specifies the simultaneous action of every drone. Thus, $A=A_1\times\dots\times A_N$ and $|A|=26^N$. For example, two drones have $26^2=676$ joint actions.
  \item \textbf{Transition function} $T(s,a,s') = T_{known}$
  \item \textbf{Reward function} for $N$ drones is the sum over all drones:
  \[
    R(s,a,s') = \sum_{i=1}^{N} R_i(s,a,s'),
  \]
  where
  \[
    R_i(s,a,s') = -1 + \begin{cases}
      -50, & \text{if drone $i$ collides},\\
      100, & \text{if drone $i$ reaches its goal}.
    \end{cases}
  \]
  \item \textbf{Discount factor} $\gamma$: \todo{e.g.\ 0.99}
\end{itemize}

\subsection*{B2. Approximate on-line MDP solver}

\paragraph{Overview.} We use Monte Carlo Tree Search (MCTS) with UCT selection and a greedy rollout policy. At each decision step, the planner builds a search tree rooted at the current joint state within the available planning time (at most 10 seconds, without parallelisation). It estimates action values through sampled transitions and discounted returns, then executes the action with the highest estimated value at the root. Sampling avoids enumerating all possible successor states, although a large joint action space remains a limitation.

\subsubsection*{Component specification}
\begin{itemize}[leftmargin=*, itemsep=0.5em]
  \item \textbf{Selection:} Randomly select an untried action first. Once every action has been tried, use UCB to select $a \leftarrow \arg\max_a \big[Q(s,a)+c\sqrt{\ln N(s)/N(s,a)}\big]$.
  \item \textbf{Expansion:} Add one new child for the sampled successor state and initialise its visit counts and action values to zero.
  \item \textbf{Simulation:} Use a greedy rollout: each drone moves closest to its goal. Estimate the new child's value by the discounted return $\hat V=\sum_{t=0}^{T-1}\gamma^t r_t$, stopping at a terminal state or the rollout depth limit.
  \item \textbf{Backpropagation:} Back up the discounted return to the root, updating the mean action value $Q(s,a)$ and incrementing the visit counts at each step.
\end{itemize}

\clearpage
\subsubsection*{Pseudocode}

Let $A$ be the set of joint-action integers, $\gamma$ the configured discount factor, $H$ the search depth limit (the configured maximum number of steps), and $c>0$ the UCB exploration constant. Each node $v$ stores its joint state $s(v)$, action counts $N(v,a)$, mean returns $Q(v,a)$, and successor nodes $C(v,a,s')$; its visit count is $N(v)=\sum_{a} N(v,a)$. A new node has zero counts and values, and no children; untried actions are represented implicitly. Each iteration descends the tree iteratively, records the visited $(v,a,r)$ triples in a path, and backs up the return along that path in reverse. All functions share the planning deadline.

\SetKwProg{Fn}{Function}{:}{end}
\SetKwFunction{Plan}{Plan}
\SetKwFunction{Select}{Select}
\SetKwFunction{Rollout}{Rollout}
\SetKwFunction{Greedy}{GreedyJointAction}

\SetAlgoNlRelativeSize{-1}

\begin{algorithm}[H]
\small
\caption{Online MCTS with UCT selection}
\label{alg:mcts-uct}
\Fn{\Plan{$s_0$, timeBudget}}{
  $root \leftarrow \NewNode(s_0)$\;
  $deadline \leftarrow now() + timeBudget$\;
  \While{$now() < deadline$}{
    $path \leftarrow [\,]$; $v \leftarrow root$; $d \leftarrow H$; $G \leftarrow 0$\;
    \tcp{Selection, expansion and simulation}
    \While{$d>0$ and $now() < deadline$}{
      $a \leftarrow \Select(v)$\;
      $(s',r,done,info) \leftarrow env.simulate(s(v),a)$\;
      append $(v,a,r)$ to $path$; $d \leftarrow d-1$\;
      \If{$done$}{\textbf{break}\;}
      \If{$C(v,a,s')$ does not exist}{
        $C(v,a,s') \leftarrow \NewNode(s')$\;
        $G \leftarrow \Rollout(s',d)$\;
        \textbf{break}\;
      }
      $v \leftarrow C(v,a,s')$\;
    }
    \tcp{Backpropagation}
    \ForEach{$(v,a,r)$ in $path$, in reverse order}{
      $G \leftarrow r+\gamma G$\;
      $N(v,a) \leftarrow N(v,a)+1$\;
      $Q(v,a) \leftarrow Q(v,a)+\frac{G-Q(v,a)}{N(v,a)}$\;
    }
  }
  \If{no action has been tried at $root$}{
    \Return \Greedy{$s_0$}\;
  }
  \Return $\arg\max_{a:\,N(root,a)>0} Q(root,a)$\;
}
\BlankLine
\Fn{\Select{$v$}}{
  \If{there exists $a\in A$ with $N(v,a)=0$}{
    \Return a uniformly sampled untried joint action\;
  }
  \Return $\arg\max_{a\in A}\left[Q(v,a)+c\sqrt{\frac{\ln N(v)}{N(v,a)}}\right]$\;
}
\end{algorithm}

\clearpage
\begin{algorithm}[H]
\small
\caption{Greedy rollout and joint-action construction}
\label{alg:greedy-rollout}
\Fn{\Rollout{$s,d$}}{
  $G \leftarrow 0$; $w \leftarrow 1$\;
  \For{$t\leftarrow 1$ \KwTo $d$}{
    \If{$now() \ge deadline$}{\textbf{break}\;}
    $a \leftarrow \Greedy(s)$\;
    $(s',r,done,info) \leftarrow env.simulate(s,a)$\;
    $G \leftarrow G+w\,r$\;
    \If{$done$}{\textbf{break}\;}
    $s \leftarrow s'$; $w \leftarrow w\gamma$\;
  }
  \Return $G$\;
}
\BlankLine
\Fn{\Greedy{$s$}}{
  \For{each drone $i$}{
    \eIf{drone $i$ has already reached its goal}{
      $a_i \leftarrow 0$ \tcp*{The simulator keeps it at its goal.}
    }{
      $F_i \leftarrow$ moves with intended destinations inside free grid cells\;
      \eIf{$F_i\ne\varnothing$}{
        $a_i \leftarrow \arg\min_{u\in F_i}\|p_i+\Delta(u)-g_i\|_2$\;
        Break ties uniformly at random\;
      }{
        $a_i \leftarrow$ uniformly sample a per-drone action\;
      }
    }
  }
  \Return $\sum_{i=1}^{N}a_i m^{i-1}$, where $m$ is the number of per-drone actions\;
}
\end{algorithm}
\endgroup

\noindent Here $p_i$ and $g_i$ are drone $i$'s current and goal positions, and $\Delta(u)$ is the displacement of per-drone action $u$. Action indices run from $0$ to $m-1$, where $m=8$ without altitude changes and $m=26$ otherwise. The grid size, obstacle cells, goal positions and per-drone moves are read from the environment configuration (\texttt{get\_config()}), so the planner only uses \texttt{simulate}, \texttt{get\_config} and \texttt{num\_actions}. The greedy policy evaluates intended destinations only; the simulator samples actual motion and detects both obstacle and inter-drone collisions. Each simulated transition uses the simulator's reward and terminal signal. Since transitions are stochastic, the same action can have multiple successor nodes. When the depth limit or deadline is reached, the remaining return is approximated as zero. The main execution loop applies the selected action using \texttt{env.step}, observes the next joint state, and calls \Plan{} again.
