\subsection*{A1. State abstraction of the 1-D grid MDP}

No. Abstracting the state into $L$ and $R$ does not turn this into an MDP. An MDP assumes the agent knows exactly which state it is in. Here the true state is still uncertain: we only believe the agent is somewhere on the left side or the right side, not exactly where. The agent therefore still needs a belief, a probability distribution over the possible states, so the problem remains a POMDP.

\paragraph{(b) Pruning by pointwise dominance.}
From Figure~\ref{fig:alpha-vectors}, $\alpha_4$ and $\alpha_5$ lie strictly below the maximum for every belief $p\in[0,1]$, so both can be removed by pointwise dominance. The maximum is
\[
V_{\max}(p)=\begin{cases}
V_{\alpha_2}(p)=10-15p, & 0\le p\le 0.4,\\
V_{\alpha_3}(p)=4, & 0.4<p<0.6,\\

\subsection*{A3. Pedestrian avoidance: MDP vs POMDP}

\paragraph{Scenario where MDP is suitable.}
\begin{itemize}[nosep]
  \item S: [car\_position, pedestrian\_position]
  \item A: [Stay, Move]
\end{itemize}
Sensors accurately identify both positions. Assume movement is discrete and the next state depends only on the current positions and action. An MDP policy maps the observed state to the best action: if a pedestrian blocks the cell ahead, choose Stay; otherwise, choose Move when safe. Since the complete state is observed, a POMDP belief is unnecessary.

\paragraph{Scenario where POMDP is suitable.}
\begin{itemize}[nosep]
  \item S: [car\_position, pedestrian\_position, destination], destination $\in$ \{cross, footpath\} (hidden)
  \item A: [Stay, Move]
  \item O: [car\_position, pedestrian\_position]
  \item T: the pedestrian moves stochastically toward their destination
  \item Z: both positions are observed exactly; the destination is not observed
  \item R: step cost, large penalty for hitting the pedestrian
  \item $b_0$: uniform over destination
\end{itemize}
Sensors give both positions, but not where the pedestrian is going. At each step the car picks the action with the highest expected value under its current belief: if $b(\text{cross})$ is high, Move risks a collision, so it chooses Stay; if low, Move is safe. After acting, it observes the new positions and updates $b(\text{destination})$ using T and Z.

\subsection*{B1. MDP framing of multi-drone navigation}

\begin{itemize}
  \item \textbf{State space} $S$: each state contains the positions of all $N$ drones, $s=(p_1,\dots,p_N)$, where $p_i=(x_i,y_i,z_i)$. 
  \item \textbf{Action space} $A$: A joint action $a=(a_1,\dots,a_N)$ specifies the simultaneous action of every drone. Thus, $A=A_1\times\dots\times A_N$ and $|A|=26^N$. For example, two drones have $26^2=676$ joint actions.
  \item \textbf{Transition function} $T(s,a,s') = T_{known}$
  \item \textbf{Reward function} for $N$ drones is the sum over all drones:
  \[
    R(s,a,s') = \sum_{i=1}^{N} R_i(s,a,s'),
  \]
  where
  \[
    R_i(s,a,s') = -1 + \begin{cases}
      -50, & \text{if drone $i$ collides},\\
      100, & \text{if drone $i$ reaches its goal}.
    \end{cases}
  \]
  \item \textbf{Discount factor} $\gamma$: \todo{e.g.\ 0.99}
\end{itemize}

\subsection*{B2. Approximate on-line MDP solver}

The current \texttt{planner.py} implements centralised Monte Carlo Tree Search (MCTS) with \emph{per-drone} UCB action statistics and sequential action assembly. There is one tree over the complete multi-drone state, rather than a separate tree for each drone. Selection chooses individual actions in drone-index order, then combines them for the simulator. A fresh tree is built for every real decision; selection, expansion, greedy rollout and backpropagation repeat until the wall-clock budget expires.

\paragraph{State, actions and node statistics.}
A node stores a copy of the simulator state: each drone's three coordinates and reached-goal flag. Let $n$ be the number of drones and $m\in\{8,26\}$ the number of moves per drone, depending on whether altitude changes are allowed. Active drones have no stay action. The simulator's action-vector order is preserved, and the combined action is encoded as
\[
  a=\sum_{i=0}^{n-1} a_i m^i,
\]
so drone 0 is the least significant digit. Actions for drones already at their goals are ignored by the simulator.

Each new node initialises two $n\times m$ arrays to zero: $N_v(i,u)$ counts updates for drone $i$ choosing move $u$ at node $v$, and $Q_v(i,u)$ is its mean sampled \emph{team} return. Its child dictionary is initially empty. For four drones with 26 moves, each statistics array has $4\cdot26=104$ entries instead of $26^4=456\,976$. This reduces the action-statistics table; the simulator still takes joint actions, and the tree can still branch over many action--outcome combinations.

\paragraph{1. Selection.}
For each active drone, selection uses
\[
 U_v(i,u)=
 \begin{cases}
  +\infty, & N_v(i,u)=0,\\[2pt]
  Q_v(i,u)+\sqrt{\dfrac{2\ln\!\left(\max\{1,\sum_b N_v(i,b)\}\right)}{N_v(i,u)}},
      & N_v(i,u)>0.
 \end{cases}
\]
Equal maxima, including multiple infinite values, are broken uniformly at random using the seeded planner RNG.

Before choosing, all reached drones' cells are reserved. Each active drone excludes out-of-grid and obstacle targets, then takes its highest-UCB candidate. If its intended target is reserved, it rejects that candidate and tries another. Accepted targets are reserved for later drones. A rejected candidate is not permanently marked invalid. Algorithm~\ref{alg:select} expresses this filtering equivalently by excluding all currently reserved targets before maximisation.

\begin{algorithm}[H]
\small
\caption{\textsc{Select}$(v)$: per-drone UCB and sequential reservations}
\label{alg:select}
$O\leftarrow\{$positions of all reached drones in $v.\mathrm{state}\}$; $\mathbf{a}\leftarrow\mathbf{0}$\;
\For{$i\leftarrow0$ \KwTo $n-1$}{
  \If{drone $i$ has reached its goal}{\textbf{continue}\;}
  $C\leftarrow\{u:\mathrm{target}(i,u)\text{ is in bounds, not an obstacle, and not in }O\}$\;
  \If{$C=\varnothing$}{\Return{$\mathrm{NONE}$}\;}
  $a_i\leftarrow$ uniformly random member of $\arg\max_{u\in C} U_v(i,u)$\;
  $O\leftarrow O\cup\{\mathrm{target}(i,a_i)\}$\;
}
\Return{$\sum_i a_i m^i$}\;
\end{algorithm}

\paragraph{2. Expansion.}
For every selected combined action, \texttt{env.simulate} samples a fresh transition $(s',r,\mathrm{done},\mathrm{info})$, including when that action has been tried before. Children are keyed by the action ID and next-state bytes (\texttt{s'.tobytes()}), so distinct sampled next states for the same action have distinct children. An absent key creates a new node; an existing key reuses its child. A terminal transition stops the search path. A new nonterminal child starts a rollout; an existing nonterminal child permits further tree selection. The transition model and reward are supplied by the simulator, rather than learned by the planner.

\paragraph{3. Greedy rollout.}
\textsc{GreedyAction} chooses drones sequentially with the same target reservations as selection, but minimises Euclidean distance from the intended next position to that drone's own goal. Equal distances keep the first move in simulator action order. It does not search for a shortest path around obstacles or revise earlier drones' choices.

\begin{algorithm}[H]
\small
\caption{\textsc{GreedyAction}$(s)$}
\label{alg:greedy-action}
$O\leftarrow\{$positions of all reached drones in $s\}$; $\mathbf{a}\leftarrow\mathbf{0}$\;
\For{$i\leftarrow0$ \KwTo $n-1$}{
  \If{drone $i$ has reached its goal}{\textbf{continue}\;}
  $C\leftarrow\{u:\mathrm{target}(i,u)\text{ is in bounds, not an obstacle, and not in }O\}$\;
  \If{$C=\varnothing$}{\Return{$\mathrm{NONE}$}\;}
  $a_i\leftarrow$ first member of $\arg\min_{u\in C}\lVert\mathrm{target}(i,u)-\mathrm{goal}_i\rVert_2$\;
  $O\leftarrow O\cup\{\mathrm{target}(i,a_i)\}$\;
}
\Return{$\sum_i a_i m^i$}\;
\end{algorithm}

\begin{algorithm}[H]
\small
\caption{\textsc{Rollout}$(s,h,\mathrm{deadline})$}
\label{alg:greedy-rollout}
$\hat{s}\leftarrow\mathrm{copy}(s)$; $G\leftarrow0$; $w\leftarrow1$\;
\If{all drones have reached their goals}{\Return{$G$}\;}
\For{$t\leftarrow1$ \KwTo $h$}{
  \If{$\mathrm{now}\geq\mathrm{deadline}$}{\textbf{break}\;}
  $a\leftarrow\textsc{GreedyAction}(\hat{s})$\;
  \If{$a=\mathrm{NONE}$ or $\mathrm{now}\geq\mathrm{deadline}$}{\textbf{break}\;}
  $(\hat{s},r,\mathrm{done},\_)\leftarrow\texttt{env.simulate}(\hat{s},a)$\;
  $G\leftarrow G+w r$; $w\leftarrow\gamma w$\;
  \If{done}{\textbf{break}\;}
}
\Return{$G$}\;
\end{algorithm}

Rollout transitions do not add tree nodes or update action statistics directly. A collision includes the simulator's penalty and terminates that rollout; the action that led to it remains available for future sampling. At a depth, time or action-availability cutoff, the continuation beyond the sampled rewards is zero; there is no heuristic bootstrap value.

\paragraph{4. Backpropagation.}
Starting with the rollout return, traverse the recorded tree path backwards and apply $G\leftarrow r+\gamma G$, where $\gamma=\texttt{discount\_factor}$. Decode each combined action, and update every drone that was active in that node's state:
\[
 N_v(i,a_i)\leftarrow N_v(i,a_i)+1,\qquad
 Q_v(i,a_i)\leftarrow Q_v(i,a_i)+\frac{G-Q_v(i,a_i)}{N_v(i,a_i)}.
\]
All selected active drones receive the same full team return, without division by the number of drones or individual reward attribution. Thus $Q_v(i,u)$ averages returns across the other drones' sampled choices; it does not isolate that drone's contribution. Drones already at their goals in the parent state receive no update, while a drone reaching its goal on this transition does.

\paragraph{Search loop and returned action.}
The horizon $D=\texttt{max\_num\_steps}$ bounds tree transitions plus rollout transitions per search iteration. It is reset for every call to \texttt{plan()}, rather than reduced by the number of real episode steps already executed. Algorithm~\ref{alg:plan} summarises the control flow; \textsc{Expand} is the transition-and-child lookup described above, and \textsc{Backpropagate} applies the preceding updates.

\begin{algorithm}[H]
\small
\caption{\textsc{Plan}$(s,\mathrm{budget})$}
\label{alg:plan}
$\mathrm{deadline}\leftarrow\mathrm{now}+\mathrm{budget}$\;
\If{all drones have reached their goals}{\Return{$0$}\;}
$\mathrm{root}\leftarrow\textsc{NewNode}(s)$; $f\leftarrow\mathrm{NONE}$; $D\leftarrow\texttt{max\_num\_steps}$\;
\While{$D>0$ and $\mathrm{now}<\mathrm{deadline}$}{
  $v\leftarrow\mathrm{root}$; $P\leftarrow[\,]$; $d\leftarrow0$; $G\leftarrow0$\;
  \While{$d<D$ and $\mathrm{now}<\mathrm{deadline}$}{
    $a\leftarrow\textsc{Select}(v)$\;
    \If{$\mathrm{now}\geq\mathrm{deadline}$}{\textbf{break}\;}
    \If{$a=\mathrm{NONE}$}{
      \If{$P\neq[\,]$}{$G\leftarrow\textsc{Rollout}(v.\mathrm{state},D-d,\mathrm{deadline})$\;}
      \textbf{break}\;
    }
    $(c,r,\mathrm{done},\_,\mathrm{isNew})\leftarrow\textsc{Expand}(v,a)$\;
    Append $(v,a,r)$ to $P$; $d\leftarrow d+1$\;
    \If{$v=\mathrm{root}$}{$f\leftarrow a$\;}
    \If{done}{\textbf{break}\;}
    \If{isNew}{
      $G\leftarrow\textsc{Rollout}(c.\mathrm{state},D-d,\mathrm{deadline})$; \textbf{break}\;
    }
    $v\leftarrow c$\;
  }
  $\textsc{Backpropagate}(P,G)$\;
}
$a\leftarrow\textsc{BestAction}(\mathrm{root})$\;
\If{$a\neq\mathrm{NONE}$}{\Return{$a$}\;}
\If{$f\neq\mathrm{NONE}$}{\Return{$f$}\;}
$a\leftarrow\textsc{GreedyAction}(s)$\;
\If{$a=\mathrm{NONE}$}{raise RuntimeError\;}
\Return{$a$}\;
\end{algorithm}

\textsc{BestAction} assembles a move sequentially using only tried per-drone actions ($N_v(i,u)>0$), maximising $Q_v(i,u)$ with uniform random tie breaking and the same target reservations. The resulting combination need not have been simulated jointly. If this assembly fails, the planner returns the most recently simulated root action; if there is none, it tries the greedy policy. Failure of that final policy raises an error, even though a different earlier assignment might have been feasible. Deadline checks occur between operations, so the budget is a stopping target rather than a strict bound on execution time.

\paragraph{Practical limits.}
Reservations prevent duplicate \emph{intended} endpoints and intended obstacle entries. They do not guarantee collision-free stochastic outcomes or check edge swaps and crossing paths. Fixed drone order can favour earlier drones, and the shared team return gives only coarse credit assignment. The UCB bonus has a fixed scale while $Q$ uses unnormalised discounted team rewards; consequently large reward differences can dominate exploration among tried actions. These are properties of the implementation, not measured improvements over the earlier planner.
